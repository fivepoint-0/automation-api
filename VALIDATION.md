# Zod Validation for Automation API

This document describes the Zod validation system added to the automation API for validating incoming requests.

## Overview

The validation system provides:
- Type-safe validation schemas for all API request types
- Validated API classes that automatically validate inputs
- Comprehensive error handling with detailed validation messages
- Full TypeScript integration

## Features

### Validation Schemas

#### Automation Schemas
- `AutomationSchema` - Base automation object validation
- `AutomationCreateRequestSchema` - Validates automation creation requests
- `AutomationUpdateRequestSchema` - Validates automation update requests (requires id + partial fields)
- `AutomationDeleteRequestSchema` - Validates automation deletion requests (requires id)
- `AutomationReadRequestSchema` - Validates automation read/filter requests (all fields optional)

#### Transaction Schemas
- `TransactionSchema` - Base transaction object validation
- `TransactionCreateRequestSchema` - Validates transaction creation requests
- `TransactionUpdateRequestSchema` - Validates transaction update requests (requires id + partial fields)
- `TransactionDeleteRequestSchema` - Validates transaction deletion requests (requires id)
- `TransactionReadRequestSchema` - Validates transaction read/filter requests (all fields optional)
- `TransactionTypeSchema` - Validates transaction type enum ('incoming' | 'outgoing')

### Validated API Classes

Use `ValidatedAutomationApi` and `ValidatedTransactionApi` instead of the base API classes to get automatic validation:

```typescript
import { ValidatedAutomationApi, ValidatedTransactionApi } from '@/api';
import { ValidationError } from '@/validation';

// Create validated API instances
const automationApi = new ValidatedAutomationApi(dataSource);
const transactionApi = new ValidatedTransactionApi(dataSource);

// All method calls are automatically validated
try {
  const automation = await automationApi.create({
    name: "My Automation",
    description: "A test automation"
  });
} catch (error) {
  if (error instanceof ValidationError) {
    console.log('Validation errors:', error.errors);
  }
}
```

### Validation Utilities

```typescript
import { validateData, validateDataWithError, ValidationError } from '@/validation';
import { AutomationCreateRequestSchema } from '@/validation';

// Option 1: Get validation result with success/failure info
const result = validateData(AutomationCreateRequestSchema, userInput);
if (result.success) {
  // Use result.data (validated and typed)
} else {
  // Handle result.errors array
}

// Option 2: Throw ValidationError on failure
try {
  const validatedData = validateDataWithError(AutomationCreateRequestSchema, userInput);
  // Use validatedData (validated and typed)
} catch (error) {
  if (error instanceof ValidationError) {
    // Handle error.errors array
  }
}
```

## Validation Rules

### Automation Fields
- `id`: Required string, minimum 1 character
- `name`: Required string, minimum 1 character
- `description`: Required string, minimum 1 character

### Transaction Fields
- `id`: Required string, minimum 1 character
- `automationId`: Required string, minimum 1 character
- `timestamp`: Required string, must be valid ISO 8601 datetime
- `status`: Required string, minimum 1 character
- `success`: Required boolean
- `message`: Required string, minimum 1 character
- `type`: Required enum, must be 'incoming' or 'outgoing'

### Request Type Rules
- **Create requests**: All fields required except `id` (generated by system)
- **Update requests**: `id` required, all other fields optional (partial update)
- **Delete requests**: Only `id` required
- **Read requests**: All fields optional (used for filtering)

## Error Handling

Validation errors provide detailed messages:

```typescript
// Example validation error
{
  success: false,
  errors: [
    "name: Name is required",
    "timestamp: Invalid timestamp format",
    "type: Invalid enum value. Expected 'incoming' | 'outgoing', received 'invalid'"
  ]
}
```

## Usage Examples

### Creating an Automation
```typescript
const createRequest = {
  name: "Email Automation",
  description: "Sends automated emails"
};
const automation = await validatedAutomationApi.create(createRequest);
```

### Creating a Transaction
```typescript
const transactionRequest = {
  automationId: "auto-123",
  timestamp: "2022-01-01T12:00:00Z",
  status: "pending",
  success: false,
  message: "Transaction initiated",
  type: "outgoing" as const
};
const transaction = await validatedTransactionApi.create(transactionRequest);
```

### Updating with Partial Data
```typescript
// Only update the status and success fields
const updateRequest = {
  id: "txn-456",
  status: "completed",
  success: true
};
const updatedTransaction = await validatedTransactionApi.update(updateRequest);
```

### Reading with Filters
```typescript
// Find all incoming transactions for a specific automation
const readRequest = {
  automationId: "auto-123",
  type: "incoming" as const
};
const transactions = await validatedTransactionApi.read(readRequest);
```

## Migration Guide

To migrate from existing API classes to validated versions:

1. Replace imports:
```typescript
// Before
import { AutomationApi, TransactionApi } from '@/api';

// After
import { ValidatedAutomationApi, ValidatedTransactionApi } from '@/api';
```

2. Update instantiation:
```typescript
// Before
const automationApi = new AutomationApi(dataSource);

// After
const automationApi = new ValidatedAutomationApi(dataSource);
```

3. Add error handling:
```typescript
import { ValidationError } from '@/validation';

try {
  await automationApi.create(data);
} catch (error) {
  if (error instanceof ValidationError) {
    // Handle validation errors
    console.log('Validation failed:', error.errors);
  } else {
    // Handle other errors
    throw error;
  }
}
```

The validated APIs are drop-in replacements that maintain the same interface while adding validation.
